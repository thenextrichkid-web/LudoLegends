3. OTP LOGIN FLOW (DEV MODE)
================================================================

  IMPORTANT: The app is in DEVELOPMENT mode.
  The OTP is ALWAYS "123456" - no real SMS is sent.

  Steps:
  -------
  1. Open the app (splash screen loads briefly)
  2. You'll see the OTP Screen with a phone number input
  3. The "+91" prefix is shown - just type your 10-digit number
     Example: 9876543210 (this becomes +919876543210)
  4. Tap "Send OTP"
     - On server, a dev OTP "123456" is stored in Redis (5-min TTL)
     - The server logs will print: [DEV] OTP for +919876543210: 123456
  5. You'll navigate to the Verify OTP screen
  6. Enter: 1 2 3 4 5 6
  7. Tap "Verify"
  8. If the phone matches a seeded account, you're logged in
  9. You'll see the Home Screen

  IMPORTANT PHONE FORMAT:
  - The OTP screen prepends "+91" to your input automatically
  - So type "9876543210" and the app sends "+919876543210"
  - This must match the format stored in the database
  - Seeded accounts use the format: +91XXXXXXXXXX

  What happens on verify:
  - Server validates the OTP against Redis (not hardcoded!)
  - If OTP is wrong or expired -> error shown with specific message
  - If OTP is correct -> JWT access + refresh tokens saved
  - Tokens stored in secure storage, user navigated to Home

  TIP: If you get "OTP expired or not requested":
  - Go back to the OTP screen
  - Enter your phone number again
  - Tap "Send OTP" to get a fresh OTP
  - Enter 123456 again

8. TROUBLESHOOTING
================================================================

  Problem: "Connection refused" or blank screen
  Solution: The server may be restarting. Wait 10 seconds and refresh.
           Check health: http://35.193.127.84:8000/health

  Problem: "OTP expired or not requested" (400 error)
  Solution: The OTP was already used or the 5-minute window expired.
           Go back to the OTP screen and request a new OTP.
           Remember: each OTP is single-use.

  Problem: "Invalid OTP" (400 error)
  Solution: Make sure you're entering 123456 (dev mode OTP).
           Also make sure the phone number matches exactly:
           - For admin: enter 0000000000 (becomes +910000000000)
           - For player: enter 9876543210 (becomes +919876543210)

  Problem: "Verification failed" snackbar on APK
  Solution: This was a bug in v1.0.0 where the app tried to parse
           the login response as a User object. Fixed in v1.0.1.
           Download the latest APK from:
           http://35.193.127.84:8000/download/apk

  Problem: APK install fails with "Insufficient storage"
  Solution: Free up phone storage. APK is ~174MB + needs
           extraction space. Minimum 500MB free recommended.

  Problem: API calls fail on PWA (mixed content)
  Solution: N/A - The PWA and API are served from the same port.
           Both are at http://35.193.127.84:8000

  Problem: Emulator can't connect to server
  Solution: The APK connects to http://35.193.127.84:8000 (GCP VM).
           The emulator needs internet access to reach it.
           Make sure your PC has internet access.

  Problem: Admin dashboard shows "401 Unauthorized"
  Solution: Login with 0000000000 / 123456 (Super Admin account).
           Note: on the admin dashboard login, enter just the
           10 digits without the +91 prefix.

  Problem: "User not found. Request OTP first."
  Solution: You must request OTP BEFORE verifying. The OTP request
           creates the user record if it doesn't exist. Always
           go through the full flow: enter phone -> Send OTP -> Verify.

  Problem: APK download link is very slow
  Solution: The APK is 174MB. Download over WiFi recommended.
           The GCP VM upload speed may be limited on the free tier.

9. LOCAL DEVELOPMENT SETUP
================================================================

  Backend (Docker):
  -----------------
  cd backend-api
  docker compose up -d --build
  # API at http://localhost:8000
  # DB at localhost:5432, Redis at localhost:6379

  Flutter App:
  ------------
  cd mobile-app
  flutter pub get

  # Run on emulator (connects to GCP server by default)
  flutter run

  # Run on emulator with localhost backend
  flutter run --dart-define=API_URL=http://10.0.2.2:8000

  # Run on web (connects to same origin)
  flutter run -d chrome

  # Build APK for testing
  flutter build apk --debug

  # Build APK pointing to specific server
  flutter build apk --debug --dart-define=API_URL=http://35.193.127.84:8000

  # Build Web
  flutter build web --release

  Admin Dashboard:
  ----------------
  cd admin-dashboard
  npm install
  npm run dev
  # Dashboard at http://localhost:3001

  Environment Variables:
  ----------------------
  ENVIRONMENT=development   (enables dev OTP 123456)
  DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/ludo_legends
  REDIS_URL=redis://localhost:6379/0
  JWT_SECRET_KEY=<your-secret>
  JWT_REFRESH_SECRET_KEY=<your-secret>

  GCP VM SSH:
  -----------
  ssh -i "C:\Users\AR\.ssh\gcp_rsa_key" asr-automation@35.193.127.84

  Restart backend on GCP:
  ------------------------
  ssh into VM, then:
  cd LudoLegends/backend-api
  sudo docker compose up -d --build

  Update APK on GCP:
  ------------------
  1. Build locally: flutter build apk --debug --dart-define=API_URL=http://35.193.127.84:8000
  2. Upload: scp -i key.apk asr-automation@35.193.127.84:/tmp/ludolegends.apk
  3. The download endpoint serves from /tmp/ludolegends.apk
  4. No restart needed - file is served directly

10. NETWORK & DEPLOYMENT NOTES
================================================================

  CAN ANYONE ACCESS THIS?
  -----------------------
  YES. The GCP VM has a public IP (35.193.127.84) with port 8000
  open via a firewall rule. Anyone with the URL can:
  - Access the Flutter PWA at http://35.193.127.84:8000
  - Download the APK at http://35.193.127.84:8000/download/apk
  - Access the Admin Dashboard at http://35.193.127.84:8000/admin
  - View API docs at http://35.193.127.84:8000/docs

  This works from:
  - Any phone on any network (mobile data, WiFi, etc.)
  - Any computer with a web browser
  - Any location worldwide

  Security notes:
  - This is a DEVELOPMENT build - OTP is always 123456
  - JWT secrets are weak (change before production)
  - No HTTPS yet (HTTP only) - don't enter real credentials
  - Admin API is wide open (no rate limiting)

  Architecture:
  - GCP VM (35.193.127.84) runs: Backend API + PostgreSQL + Redis + n8n
  - Flutter PWA + Admin Dashboard served from the same FastAPI server
  - APK download served as a static file from /tmp/ludolegends.apk
  - Everything on one port: 8000

  What needs fixing before production:
  - Enable HTTPS (need a domain name for Let's Encrypt)
  - Strong JWT secrets
  - Rate limiting on auth endpoints
  - Real OTP via Twilio (or other SMS provider)
  - Environment: change ENVIRONMENT to "production"
